# Data

## Layout

```
data/
  raw/          original files from the Central Elections Committee, byte-for-byte
  parties/      party letter -> name table, one file per Knesset
  official/     official national totals used to complete partial sources (Knesset 16)
  processed/    generated by scripts/build_data.py (do not edit by hand)
```

Rebuild everything in `processed/` with:

```bash
python scripts/build_data.py
```

## Raw files

ballot box, the committee's `expb` file) or `settlements` (one row per settlement,

Raw files keep the committee's original encoding; `read_raw` detects it and drops the
empty trailing column of the older files.

Knesset 16 comes from the [elections-vote-transfer](https://github.com/harelc/elections-vote-transfer)
project in the committee layout, but with regular boxes only (no envelope votes) and no
settlements file. The build adds an envelopes row equal to the official national totals
in `data/official/knesset_16_totals.csv` minus the regular boxes. That file has the
official totals and the votes of the 17 largest lists (Wikidata / IFES ElectionGuide);
the envelope votes of the 11 smallest lists (1,707 in all) are split in proportion to
their regular votes, so they are an estimate. The raw file also ends with a DOS
end-of-file row and writes one empty list as "0.0"; the reader handles both.

Knesset 17-18 have no committee file in this repo. Their ballots file comes from the
[Israel-Elections-Map](https://github.com/Yoavfried/Israel-Elections-Map) project, which
built it from the official data.gov.il package (normalized English columns, party letters
as published, an `is_envelope` column, plus the project's geography columns, which the
build ignores). There is no settlements file: the build sums the ballots per settlement.
Envelope rows get code 9999 and 0 registered voters. Knesset 17 eligible voters per box
were recovered by the project from archived reports, not from the official file.

Knesset 26's ballots file adds two columns, `חיצוניות` (`external`) and `קלפי אחרת`
(`other_ballot`); their meaning is not documented and they are all zero.

Knesset 19-21 use an older layout: the ballot column is `מספר קלפי`, and there are no
`סמל ועדה`, `ברזל`, `ריכוז` or `שופט` columns. These columns are empty in their processed
files; nothing is filled in from other elections.

Envelopes codes differ in the raw files (99999 in Knesset 21; 875 in the Knesset 20
ballots file and 0, with an empty name, in its settlements file). The build normalizes
them to 9999 / `מעטפות חיצוניות`. The Knesset 19 settlements file has no envelopes row
at all (its totals cover regular votes only); the build adds one, summed from the 228
envelope rows (code 875) of the ballots file, so national totals match the official result.

Knesset 20 publishes split ballot boxes under one number (58 pairs, e.g. Jerusalem has
21 of them); their `ballot_key` gets `-1` / `-2` in file order, `ballot_id` stays as published.

## Geography: statistical areas

`data/raw/geography/knesset_<N>_<year>_ballot_areas.csv` (K19-K25) are the ballot files
of the [Israel-Elections-Map](https://github.com/Yoavfried/Israel-Elections-Map) project
(`public-data/v1/ballots/k<N>.csv`), downloaded by the user on 2026-10-30 and stored
byte-for-byte. Each regular box has a CBS statistical area of the 2011 vintage
(`stat_area_id`, e.g. `stat2011:3000123`); 6-8% of the boxes per election have none
(`statistical_area_pending`). The K17-K18 raw ballots files carry areas of other
vintages (1995, 2008) and K16 has none, so the area unit starts at K19. The project's
licence has not been checked yet.

`scripts/build_areas.py` (run by `build_data.py`) writes `data/processed/ballot_areas.csv`
(`knesset, ballot_key, area_id, method`) for K19-K26:

- K19-K25: the project's area, matched on settlement + ballot number (all boxes match,
  valid votes equal); boxes without an area get `loc:<settlement_code>`.
- K26 (no area file): the most common K25 area of the same polling center (`ריכוז`,
  86% of boxes), else the K25 box with the same settlement and number (3%), else the
  settlement. Checked on K24 → K25: 93% of polling centers keep their area.

## Processed files

| File | Content |
|------|---------|
| `knesset_<N>/ballots.csv` | One row per ballot box, vote counts per party |
| `knesset_<N>/settlements.csv` | One row per settlement, vote counts per party |
| `knesset_<N>/national.csv` | National votes, share, threshold and seats per party |
| `knesset_<N>_<year>.xlsx` | Excel workbook: `National`, `Settlements`, `Ballots`, `Parties` tables with formulas |
| `ballots_long.csv.gz` | All elections, one row per (ballot, party): `votes` and `share` of valid votes |
| `ballot_areas.csv` | K19-K26: statistical area (or settlement) of every regular box, see above |

`knesset_<N>/national.csv` also carries each list's `family` and `bloc`.

CSV files are UTF-8 with BOM so Excel opens the Hebrew correctly.

### Columns

| Column | Raw name | Meaning |
|--------|----------|---------|
| `ballot_key` | - | `<settlement_code>_<ballot_id>` (plus `-1`/`-2` for Knesset 20 split boxes), unique within one election |
| `ballot_uid` | ברזל | Committee's internal ballot box id |
| `committee_code` | סמל ועדה | Regional elections committee |
| `settlement_code` | סמל ישוב | CBS settlement code |
| `settlement_name` | שם ישוב | Settlement name |
| `ballot_id` | קלפי | Ballot number inside the settlement, kept as text (`3.1`, `21`) |
| `concentration` | ריכוז | As published by the committee |
| `judge` | שופט | As published by the committee |
| `registered` | בזב | Eligible voters |
| `voters` | מצביעים | Votes cast |
| `invalid` | פסולים | Invalid votes |
| `valid` | כשרים | Valid votes (= sum of party columns) |
| `is_envelopes` | - | `True` for settlement code 9999 (normalized, see above), "outer envelopes" (soldiers, diplomats, prisoners, hospitals). It has no geography and `registered = 0` |
| party letters | e.g. מחל | Valid votes for that list |

## Party tables

`data/parties/knesset_<N>_parties.csv`: `letter,name_he,name_en,family,bloc,verified,leader_he`.

- `family` - the same party across elections (used by the cross-election report and the
  party lookup).
- `leader_he` - #1 on the list in that election, filled only when a source confirms it
  (see the source list in `HANDOFF.md`); empty for unconfirmed and unnamed lists.
- `bloc` - `right`, `haredi`, `center_left`, `arab` or `other`. This is an ideological
  grouping chosen for this project and can be edited; rebuild after changing it.
  Current choice: right = Likud, Likud-Yisrael Beiteinu, National Union, NRP, Yisrael BaAliyah, National Union-NRP, Yamina, Union of Right-Wing Parties, Kulanu, Religious Zionism, New Hope, Yisrael Beiteinu,
  Jewish Home; haredi = Shas, UTJ; center-left = Blue and White, Yesh Atid, National
  Unity, Zionist Union, Hatnua, Kadima, Shinui, One Nation, Labor-Meimad, Labor, Labor-Gesher, Labor-Gesher-Meretz, Meretz, Democratic Union; other (named) = Gil Pensioners; arab = Joint List, Ra'am (United Arab List), Ra'am-Balad, Ra'am-Ta'al, Hadash, Hadash-Ta'al, Balad.

## Notes for modeling

- Settlement names change spelling between elections (`אבו גווייעד שבט` in Knesset 25,
  `אבו ג'ווייעד (שבט)` in Knesset 22); always join on `settlement_code`.
- Ballot numbering changes between elections, so `ballot_key` cannot be assumed to be
  the same physical polling station across elections. Settlement codes are stable.
- Party lists change between elections (mergers and splits). Cross-election training
  will need a mapping of lists to stable party families or blocs.
- Party tables: lists that passed the threshold are named; small lists are marked
  `verified = no` and still need names.
