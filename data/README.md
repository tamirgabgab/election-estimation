# Data

## Layout

```
data/
  raw/          original files from the Central Elections Committee, byte-for-byte
  parties/      party letter -> name table, one file per Knesset
  processed/    generated by scripts/build_data.py (do not edit by hand)
```

Rebuild everything in `processed/` with:

```bash
python scripts/build_data.py
```

## Raw files

Naming: `knesset_<N>_<year>_<level>.csv`, where `<level>` is `ballots` (one row per
ballot box, the committee's `expb` file) or `settlements` (one row per settlement,
the committee's `expc` file).

Raw files keep the committee's original encoding; `read_raw` detects it and drops the
empty trailing column of the older files.

Knesset 19-21 use an older layout: the ballot column is `מספר קלפי`, and there are no
`סמל ועדה`, `ברזל`, `ריכוז` or `שופט` columns. These columns are empty in their processed
files; nothing is filled in from other elections.

Envelopes codes differ in the raw files (99999 in Knesset 21; 875 in the Knesset 20
ballots file and 0, with an empty name, in its settlements file). The build normalizes
them to 9999 / `מעטפות חיצוניות`. The Knesset 19 settlements file has no envelopes row
at all (its totals cover regular votes only); the build adds one, summed from the 228
envelope rows (code 875) of the ballots file, so national totals match the official result.

Knesset 20 publishes split ballot boxes under one number (58 pairs, e.g. Jerusalem has
21 of them); their `ballot_key` gets `-1` / `-2` in file order, `ballot_id` stays as published.

## Processed files

| File | Content |
|------|---------|
| `knesset_<N>/ballots.csv` | One row per ballot box, vote counts per party |
| `knesset_<N>/settlements.csv` | One row per settlement, vote counts per party |
| `knesset_<N>/national.csv` | National votes, share, threshold and seats per party |
| `knesset_<N>_<year>.xlsx` | Excel workbook: `National`, `Settlements`, `Ballots`, `Parties` tables with formulas |
| `ballots_long.csv.gz` | All elections, one row per (ballot, party): `votes` and `share` of valid votes |

`knesset_<N>/national.csv` also carries each list's `family` and `bloc`.

CSV files are UTF-8 with BOM so Excel opens the Hebrew correctly.

### Columns

| Column | Raw name | Meaning |
|--------|----------|---------|
| `ballot_key` | - | `<settlement_code>_<ballot_id>` (plus `-1`/`-2` for Knesset 20 split boxes), unique within one election |
| `ballot_uid` | ברזל | Committee's internal ballot box id |
| `committee_code` | סמל ועדה | Regional elections committee |
| `settlement_code` | סמל ישוב | CBS settlement code |
| `settlement_name` | שם ישוב | Settlement name |
| `ballot_id` | קלפי | Ballot number inside the settlement, kept as text (`3.1`, `21`) |
| `concentration` | ריכוז | As published by the committee |
| `judge` | שופט | As published by the committee |
| `registered` | בזב | Eligible voters |
| `voters` | מצביעים | Votes cast |
| `invalid` | פסולים | Invalid votes |
| `valid` | כשרים | Valid votes (= sum of party columns) |
| `is_envelopes` | - | `True` for settlement code 9999 (normalized, see above), "outer envelopes" (soldiers, diplomats, prisoners, hospitals). It has no geography and `registered = 0` |
| party letters | e.g. מחל | Valid votes for that list |

## Party tables

`data/parties/knesset_<N>_parties.csv`: `letter,name_he,name_en,family,bloc,verified`.

- `family` - the same party across elections (used by the cross-election report).
- `bloc` - `right`, `haredi`, `center_left`, `arab` or `other`. This is an ideological
  grouping chosen for this project and can be edited; rebuild after changing it.
  Current choice: right = Likud, Likud-Yisrael Beiteinu, Yamina, Union of Right-Wing Parties, Kulanu, Religious Zionism, New Hope, Yisrael Beiteinu,
  Jewish Home; haredi = Shas, UTJ; center-left = Blue and White, Yesh Atid, National
  Unity, Zionist Union, Hatnua, Kadima, Labor, Labor-Gesher, Labor-Gesher-Meretz, Meretz, Democratic Union; arab = Joint List, Ra'am, Ra'am-Balad, Ra'am-Ta'al, Hadash, Hadash-Ta'al, Balad.

## Notes for modeling

- Settlement names change spelling between elections (`אבו גווייעד שבט` in Knesset 25,
  `אבו ג'ווייעד (שבט)` in Knesset 22); always join on `settlement_code`.
- Ballot numbering changes between elections, so `ballot_key` cannot be assumed to be
  the same physical polling station across elections. Settlement codes are stable.
- Party lists change between elections (mergers and splits). Cross-election training
  will need a mapping of lists to stable party families or blocs.
- Party tables: lists that passed the threshold are named; small lists are marked
  `verified = no` and still need names.
